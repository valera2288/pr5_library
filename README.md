# Практическая работа №5 — аутентификация, роли и защита маршрутов

Клиент библиотечной системы (продолжение ПР4): регистрация, вход и выход, три роли с разным набором функций, защита маршрутов через `redirect`, автоматическое обновление токена, выход по неактивности и ограничение длительности сессии.

## Запуск

Сначала сервер (нужен Node.js 18+), контракт API — в `api/КОНТРАКТ-API.md`:

```
node api/mock-server.js --port 8080 --origin http://localhost:5555
```

Для проверки обновления токена сервер запускают с коротким сроком жизни: `--ttl 60`.

Затем клиент:

```
flutter pub get
flutter run -d chrome --web-port=5555
```

Адрес сервера задаётся параметром `--dart-define=API_BASE_URL=http://192.168.1.10:8080/api`, общая длительность сессии в минутах — `--dart-define=SESSION_MAX_MINUTES=60` (по умолчанию 120).

Учётные записи: `admin/admin123`, `librarian/librarian123`, `reader/reader123`.

## Роли

| Операция | Читатель | Библиотекарь | Администратор |
|---|---|---|---|
| Просмотр каталога | да | да | да |
| Книги и справочники: создание, изменение, удаление | нет | да | да |
| Свои выдачи и продление срока | да | нет | нет |
| Оформление и закрытие выдач | нет | да | нет |
| Читатели и карточки | нет | да | да |
| Физическое удаление и восстановление | нет | нет | да |
| Пользователи и смена ролей | нет | нет | да |
| Статистика | нет | нет | да |

Права описаны в `lib/core/permissions.dart`, проверка в маршрутах — в `lib/core/router.dart`. Клиентская проверка только убирает из интерфейса недоступное: решение о праве на операцию принимает сервер по подписанному токену.

## Токены и сессия

- токены и профиль лежат в `localStorage` (`shared_preferences`) и переживают перезагрузку;
- ответ 401 (кроме адресов `/auth/`) один раз обновляет токен и повторяет запрос; одновременные 401 ждут одно обновление;
- неудачное обновление завершает сессию без повторных попыток;
- 3 минуты без действий завершают сессию, за 30 секунд показывается предупреждение; время последнего действия хранится в `localStorage`.

В учебный сервер добавлены `POST /api/loans/{id}/renew` (продление, только своя выдача, один раз) и `PATCH /api/users/{id}` (смена роли, только администратор).
